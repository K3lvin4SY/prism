# Prism settings

## How a setting works

1. **Declared** in the extension's PHP provider (`src/<Name>Provider.php`, `boot()`):
   `Setting::make('key', 'key', <default>, [<Laravel rules>])->label('…')->help('…')->tab('…')->field('toggle'|'number'|'text'|'textarea'|'select'|'password'|'color', $options)->frontend()`.
   - `->frontend()` sends it to the browser (and `->frontendType('boolean')` keeps booleans typed); without it only PHP sees it. `->public()` also sends it to signed-out pages (Prism Layout's branding). `->file($types, $kb)` makes an uploaded file setting.
   - Rules are enforced when saving. Colors must be hex or `oklch()`.
2. **Stored** by the Panel in `extension_settings` (`extension`, `key`, `value` as JSON, `scope` global). A setting never saved has no row and uses its default.
3. **Edited** in Prism Properties (`/panel/prism`, Prism Core). Sections, units, ranges and placeholders come from `prism-core/src/client/hints.ts`; complex values (JSON settings such as highlight rules, quick commands, keybinds) have editors in `prism-core/src/client/editors.tsx`.
4. **Read** in the browser through the extension's `config.ts` `read(raw)` into a typed object, via the shared store, so the live preview can lay drafts over it (see `prism-architecture`). PHP reads with `$this->settings()->get('key')` or the extension's `Support/Settings.php`.
5. **Exported** with Prism Export (all but file settings; see `prism-export-import`).

Some extensions also return their current settings from their own endpoints (`applyConfig`) so a change shows without a reload.

## Prism Themes (a theme: settings in `prism-themes/extension.json` → `theme.settings`)

Generated by `prism-themes/scripts/generate.py`. Each setting becomes a `:root` token or an `<html>` attribute, rendered server-side.

- **Palettes**, type `color`: `d_<role>` for dark and `l_<role>` for light, 19 roles each: background, surface, sidebar, raised, deep, border, text, muted_text, primary, on_primary, success, warning, danger, red, green, yellow, blue, magenta, cyan. Tokens `--pt-d-<role>` / `--pt-l-<role>`; `theme.css` maps them to the Panel's tokens (cards, sidebar, terminal ANSI, editor syntax, charts, …).
- **Type and shape**: `radius` (`--pt-radius`), `font` (`data-pt-font`: plex, system, rounded, serif, mono), `font_size` (`--pt-font-size`), `switches` (`data-pt-switches`: rounded or square).
- **Surfaces**: `surface_style` (`data-pt-surface`: flat, raised, outlined, glow, glass), `blur` (`--pt-blur`), `opacity` (`--pt-opacity`).
- **Background**: `background` (`data-pt-bg`: plain, gradient, aurora, waves, stars, mesh, grid, picture), `background_image` (`--pt-bg-image`), `background_dim` (`--pt-bg-dim`).
- **Motion**: `motion` (`data-pt-motion`).
- **Bookkeeping**: `preset` (name of the preset the look came from), `presets` (the admin's own presets as JSON). Built-in presets live in `prism-core/src/client/themes/presets.ts` and `builtins.json`.

## Notes on particular settings

- **Prism Layout navigation**: `bars`, `bars_tablet`, `bars_mobile` take `sidebar`, `top`, `dock`, `dock_expand` (expandable dock: main pages plus a button that opens the area's pages upwards), `sidebar_top`, `rail`, `rail_top`, `top_dock`; tablets and phones also `same` (follow the next size up). `barsFor(settings, useDevice())` in `prism-layout/src/client/settings.ts` picks the one for the device; on phones a sidebar or rail opens from a menu button, on tablets and computers it sits beside the page.
- **Prism Layout `egg_colors`** is `none`, `color` or `logo`; older saved booleans read as `color` (true) or `none` (false). Logos show on Rows cards only; egg logos are uploaded per egg in Prism Properties (stored in `prism_layout_pictures`, kind `egg-logo`), with built-in tag defaults in `prism-layout/src/client/logos/`. Card colors come from the Panel's tag colors (`/api/client/extensions/prism-layout/tags`).
- **Prism Console** settings are defaults; people's own choices (`allow_*`) are stored as preferences and win.
- **Prism File Browser** editor settings and `keybinds` are defaults; people override them in the editor's settings tab when `allow_editor_settings` is on. `hidden_paths`/`protected_paths` are newline lists of glob patterns, enforced by its PHP.
- **Prism MC / Prism Terraria `egg_tags`**: comma-separated egg tags that mark a server as Minecraft or Terraria (detection, see `prism-games`).
- **`*_key` settings** are secrets (field `password`): the Panel returns a mask instead of the value and keeps the stored value when the mask is sent back, and `->frontend()` is refused for them. They never reach the browser or an export file.

## Adding a setting

1. Add `Setting::make(...)` in the provider with rules, label, help, tab, field and `->frontend()` if the browser needs it.
2. Read it in `config.ts` `read(raw)` with a fallback equal to the default.
3. Add a hint in `prism-core/src/client/hints.ts` if it needs a section, unit or range; an editor in `editors.tsx` if it is structured.
4. Wrap any new view or screen with `configStore.live` / `liveModule` so the live preview reaches it.
5. Deploy the extension, then Prism Core if Core changed; check it in Prism Properties and in the preview window.
